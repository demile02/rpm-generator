# Frontend Audit 001

Tanggal: 2026-10-11
Mode: AFTER
Scope: React frontend `frontend/`, served app read-only, build and lint.

Tidak ada source code, test, database, atau generated asset production yang diubah oleh audit.

## Verifikasi

- `npm run build`: PASS
  - JavaScript: 264.49 kB raw, 78.18 kB gzip
  - CSS: 40.82 kB raw, 9.29 kB gzip
  - Satu JavaScript chunk awal.
- `npm run lint`: PASS dengan warning `react(set-state-in-effect)` pada beberapa screen.
- `node ui/tests/frontend.test.js`: PASS, 165/165.
- `pytest -q tests/test_frontend_ui.py`: PASS.
- `npx tsc -p tsconfig.app.json --noEmit --pretty false`: PASS.

- Tidak ada full click-through browser untuk seluruh kontrol React. Harness yang ada terutama menguji legacy `ui/`, bukan lifecycle React.

## Temuan performa

### 1. Drag shortcut merender ulang preview besar dan menulis localStorage pada setiap pointermove

Priority: HIGH

Lokasi:
- `frontend/src/screens/Hasil.tsx:268-274`
- `frontend/src/screens/Hasil.tsx:346-358`
- `frontend/src/screens/Hasil.tsx:388-390`

Bukti:
- `geserShortcut()` memanggil `setShortcutPosition()` pada setiap pointer event.
- Effect posisi langsung menjalankan `JSON.stringify()` dan `localStorage.setItem()`.
- Render ulang memanggil `renderModuleParts(m)`.

Dampak: drag mobile memicu reconciliation React, transformasi RPM penuh, update DOM, dan synchronous storage write pada frekuensi pointer event.

Perbaikan minimal: simpan koordinat drag di ref, ubah transform DOM melalui `requestAnimationFrame`, commit state dan localStorage sekali pada `pointerup`.

### 2. Transformasi seluruh RPM berjalan pada setiap render Hasil

Priority: HIGH

Lokasi:
- `frontend/src/screens/Hasil.tsx:388-390`
- `frontend/src/lib/moduleRender.ts:222-456`

Bukti: `renderModuleParts()` memetakan identitas, KBC, TP, KKTP, praktik, pertemuan, aktivitas, asesmen, glosarium, dan daftar isi. State shortcut, warning, versi, dialog, dan status dapat memicu render ulang.

Dampak: interaksi kecil membangun ulang data untuk seluruh dokumen dan tree besar.

Perbaikan minimal: `useMemo(() => renderModuleParts(module), [module])`. Pecah tabel atau section besar menjadi komponen memoized bila masih lambat.

### 3. Navigasi hash memaksa remount dan fetch ulang

Priority: HIGH

Lokasi:
- `frontend/src/App.tsx:71-81`
- `frontend/src/App.tsx:349-354`
- `frontend/src/screens/Formulir.tsx:234-240, 345-356`
- `frontend/src/screens/Beranda.tsx:121-125`

Bukti: `layarKey` berubah setiap membuka Beranda, Arsip, atau Formulir. Key baru memaksa unmount dan mount. Formulir mengulang `/api/curriculum/options` dan `/api/buku`; Beranda mengulang `/api/buku` dan `/api/modules`.

Runtime: kembali ke Formulir mengulang request curriculum sekitar 138,973 byte decoded, selain request buku.

Dampak: latency navigasi, parsing JSON, beban server, dan hilangnya state lokal screen.

Perbaikan minimal: cache hasil query di shared state, invalidasi setelah upload/delete/archive/import, dan hilangkan remount bila refresh tidak diperlukan.

### 4. Semua screen masuk initial JavaScript chunk

Priority: MEDIUM-HIGH

Lokasi:
- `frontend/src/App.tsx:4-13`
- `frontend/vite.config.ts:6-13`

Bukti: Landing, Beranda, Arsip, Formulir, Progres, Hasil, dan Editor static import. Build menghasilkan satu chunk `264.49 kB` raw, `78.18 kB` gzip.

Dampak: pengguna Landing mengunduh kode Editor, preview, tabel, dan form sebelum membutuhkannya.

Perbaikan minimal: gunakan `React.lazy` dan `Suspense` untuk screen berat. Pertahankan Shell dan navigasi eager. Prefetch screen berikutnya saat idle jika perlu.

### 5. AppContext global membuat Shell ikut rerender saat progress berubah

Priority: MEDIUM-HIGH

Lokasi:
- `frontend/src/state/appContext.tsx:70-105`
- `frontend/src/App.tsx:34-38, 346-398`
- `frontend/src/screens/Progres.tsx:80-90`
- `frontend/src/screens/Beranda.tsx:210-213`

Bukti: loading status, alert, profil, dan callback berada dalam satu context. Polling dan upload progress memperbarui context.

Dampak: update progress dapat merender ulang navigasi, screen aktif, dialog, footer, dan overlay sekaligus.

Perbaikan minimal: pisahkan loading, alert, dan profil ke context berbeda atau selector store. Batasi update upload ke animation frame atau perubahan persentase.

### 6. Editor adalah controlled form besar dengan update state top-level pada setiap ketikan

Priority: MEDIUM-HIGH

Lokasi:
- `frontend/src/screens/Editor.tsx:149-171`
- `frontend/src/screens/Editor.tsx:465-475, 587-681, 717-758`

Bukti: TP, KKTP, aktivitas, asesmen, rubrik, LKPD, glosarium, dan metadata berada dalam satu `st`. Setiap input memetakan array dan mengganti object editor.

Dampak: satu ketikan merender ulang seluruh editor, termasuk 52 textarea dan 101 input/select pada sample runtime.

Perbaikan minimal: pecah section dan row menjadi komponen memoized dengan callback stabil, atau simpan draft field di ref lalu kumpulkan saat simpan.

### 7. Scroll Formulir membaca layout dan menulis state setiap event

Priority: MEDIUM

Lokasi:
- `frontend/src/screens/Formulir.tsx:183-198`
- `frontend/src/screens/Formulir.tsx:244-309`

Bukti: handler `hitung()` memanggil `getBoundingClientRect()` dan `setLangkah()` langsung dari native scroll event. Restore draft memakai beberapa effect berantai yang melakukan setState saat mount. Lint memberi warning `react(set-state-in-effect)` pada jalur ini.

Perbaikan minimal: throttle dengan `requestAnimationFrame`, set state hanya jika langkah berubah, dan konsolidasikan inisialisasi draft.

### 8. Landing mengunduh statistik yang tidak dipakai

Priority: MEDIUM

Lokasi:
- `frontend/src/components/Landing.tsx:39-49`

Bukti: Landing hanya memakai tiga total, tetapi `/api/stats` mengirim `cp_by_subject` besar. Runtime mengukur sekitar 11,999 byte transfer dan 11,699 byte decoded.

Perbaikan minimal: endpoint summary atau query parameter yang hanya mengirim tiga total.

### 9. Operasi bulk archive, restore, dan delete berjalan serial

Priority: MEDIUM

Lokasi:
- `frontend/src/screens/Beranda.tsx:331-347, 369-385`
- `frontend/src/screens/Arsip.tsx:117-133, 155-171`

Bukti: loop menunggu request sebelumnya selesai sebelum memulai ID berikutnya.

Dampak: waktu total tumbuh linear terhadap jumlah item.

Perbaikan minimal: endpoint batch. Jika belum ada, gunakan `Promise.allSettled` dengan batas concurrency kecil dan laporan per-ID.

### 10. Grain dan blob blur fixed melakukan kerja compositor terus-menerus

Priority: LOW-MEDIUM

Lokasi:
- `frontend/src/index.css:107-129`

Bukti: grain memakai fixed `mix-blend-mode: overlay` dan SVG turbulence. Blob memakai fixed positioning, `filter: blur(60px)`, dan animasi enam detik.

Dampak: compositing full viewport dan blur dapat berat pada GPU mobile.

Perbaikan minimal: batasi dekorasi pada viewport besar atau kurangi blend/blur. Gunakan `contain: paint` dan verifikasi ulang visual.

### 11. Polling upload fixed 500 ms tanpa backoff atau pembatalan

Priority: LOW-MEDIUM

Lokasi:
- `frontend/src/api.ts:79-112`

Bukti: `kirimAsync()` memakai loop tanpa batas dengan delay 500 ms. Tidak ada `AbortSignal`, timeout, batas percobaan, atau pembatalan ketika screen unmount.

Dampak: ekstraksi panjang menghasilkan dua request status per detik dan dapat terus berjalan setelah user meninggalkan screen.

Perbaikan minimal: retry timing dari server atau backoff, `AbortController`, timeout, dan abort saat operasi dibatalkan.

## Temuan bug fungsional dan aksesibilitas

### 12. Navigasi dari Editor melewati konfirmasi perubahan belum disimpan

Priority: HIGH

Lokasi:
- `frontend/src/App.tsx:67-90`
- `frontend/src/App.tsx:162-169`
- `frontend/src/components/TopBar.tsx:40-45, 61-92`
- `frontend/src/screens/Editor.tsx:149-162`

Bukti: `tinggalkan()` tersedia, tetapi route hash Beranda, Arsip, dan Formulir langsung mengganti screen. Guard dipakai pada tombol kembali Progres, bukan seluruh navigasi Editor.

Reproduksi: buka Edit, ubah field, klik Beranda atau Arsip, lalu buka kembali RPM.

Dampak: perubahan lokal Editor hilang tanpa konfirmasi.

Perbaikan minimal: semua navigasi yang meninggalkan mode Edit harus melewati guard yang sama.

### 13. Save Editor dapat menghapus field aktivitas dan LKPD yang tidak masuk allowlist

Priority: HIGH

Lokasi:
- `frontend/src/screens/Editor.tsx:251-281`
- `frontend/src/screens/Editor.tsx:331-340`

Bukti: `actsNew` hanya membangun id, name, description, duration, tp_linked, experience, stage, meeting, type, resources. `lkNew` hanya membangun id, title, instructions, task, tp_linked.

Reproduksi: simpan RPM yang memiliki properti tambahan pada `learning_activities` atau `lkpd`, setelah mengubah satu field pada section tersebut. Bandingkan payload sebelum dan sesudah.

Dampak: field yang tidak ditampilkan editor hilang saat section dianggap berubah.

Perbaikan minimal: mulai dari object lama lalu patch field yang diedit, atau preserve semua property dengan spread dan normalisasi hanya field yang memang diedit.

### 14. Deep-link anchor hasil tidak dipulihkan setelah reload langsung

Priority: MEDIUM

Lokasi:
- `frontend/src/App.tsx:118-121`
- `frontend/src/App.tsx:52-65`
- `frontend/src/screens/Hasil.tsx:297-321`

Bukti: anchor `#a-*` dideteksi sebelum session selesai dimuat. `bukaSesi()` membuka Hasil tetapi tidak melakukan scroll setelah DOM target tersedia. Browser native scroll terjadi sebelum target async tersedia.

Reproduksi: buka URL `?generation_id=<id>#a-identitas`, reload, tunggu hasil tampil.

Perbaikan minimal: simpan anchor, lalu scroll setelah module dan target section selesai dirender.

### 15. Dialog hapus versi tidak dapat ditutup dengan Escape dan tidak memiliki accessible name

Priority: MEDIUM

Lokasi:
- `frontend/src/screens/Hasil.tsx:946-970`

Bukti: dialog memakai `role="dialog"` dan `aria-modal="true"`, tetapi tidak punya `aria-label` atau `aria-labelledby`. Tidak ada handler Escape khusus. Handler Escape global hanya menutup LogDialog.

Reproduksi: buka hasil dengan minimal dua versi, klik Hapus, tekan Escape.

Dampak: dialog tetap terbuka dan tidak memiliki nama yang dibaca assistive technology.

Perbaikan minimal: tambahkan heading ID dan `aria-labelledby`, Escape close, focus trap, dan restore focus ke tombol pemicu.

### 16. Log detail dapat menampilkan record yang salah akibat response race

Priority: MEDIUM

Lokasi:
- `frontend/src/components/LogDialog.tsx:119-135`

Bukti: request detail tidak memiliki request identity atau cancellation. Response selalu memanggil `setDetail()` walaupun `detailGid` sudah berubah.

Reproduksi: buka Log, klik Detail A, segera klik Detail B, tunda response A sampai setelah B.

Dampak: panel berlabel B dapat berisi detail A.

Perbaikan minimal: AbortController atau request token yang hanya menerima response untuk `detailGid` terbaru.

### 17. Polling upload dapat menggantung tanpa batas

Priority: MEDIUM

Lokasi:
- `frontend/src/api.ts:91-112`

Bukti: loop hanya berhenti pada error atau success. Tidak ada timeout, abort, atau batas status `running`.

Reproduksi: biarkan endpoint status terus mengembalikan `running`.

Dampak: overlay loading dapat tetap aktif selamanya.

Perbaikan minimal: timeout yang jelas, tombol batalkan atau coba lagi, dan abort ketika komponen pemilik unmount.

### 18. Tombol regenerate aktif sebelum riwayat versi selesai dimuat

Priority: LOW

Lokasi:
- `frontend/src/state/session.tsx:54-64`
- `frontend/src/screens/Hasil.tsx:395-419, 431-435`

Bukti: version awal dapat `null`, request `listVersions()` berjalan async, tetapi tombol regenerate belum disabled. Klik terlalu cepat menghasilkan pesan bahwa riwayat belum tersedia.

Perbaikan minimal: expose `versionsLoading`, disable regenerate selama request, atau antrekan action setelah versi tersedia.

### 19. Modal tidak memiliki focus trap atau focus restoration konsisten

Priority: MEDIUM

Lokasi:
- `frontend/src/components/ConfirmDialog.tsx:28-35`
- `frontend/src/components/ProfileDialog.tsx:26-33`
- `frontend/src/components/Overlays.tsx:15-49`
- `frontend/src/screens/Formulir.tsx:711-755`
- `frontend/src/screens/Progres.tsx:210-236`

Bukti: beberapa modal hanya menangani Escape atau backdrop click. Tidak ditemukan containment focus dan restore focus ke trigger.

Dampak: pengguna keyboard dapat Tab keluar modal menuju konten di belakang.

Perbaikan minimal: gunakan pola dialog tunggal dengan focus trap, Escape, `aria-labelledby`, dan restore focus.

## Catatan tambahan

- Static scan menemukan ID yang muncul di lebih dari satu file: `buka-error`, `judul-hasil`, dan `layar-hasil`. Tidak ada duplicate live DOM yang terkonfirmasi karena branch tersebut conditional, tetapi tiap conditional branch sebaiknya tetap memakai ID yang unik atau hanya render satu branch.
- Harness `ui/tests/frontend.test.js` terutama menguji legacy `ui/`. Coverage belum cukup untuk lifecycle React, focus management, async race, dan hash routing React.
- Temuan di atas belum diperbaiki. Perubahan kode memerlukan pilihan nomor temuan dari user sesuai mode AFTER.
